# Prompt 拖拽性能：本地优化记录

版本：v0.4.35。以下为发布前的离线与独立浏览器夹具验证记录；验证期间没有启动 ComfyUI 或运行用户工作流。

## 已确认并修复

1. **拖动中重复测量、反复创建指示线**：旧路径每次 dragover 都读取所有卡片的位置，再移除并重建插入指示线。现改为复用几何快照和一个指示线，只在插入位置改变时写样式。
2. **同一次排序刷新两遍**：`setTextareaValue` 的合成 input 先同步并重绘卡片，排序处理器随后更新选区、再次同步并重绘。现仅在主节点的拖放/键盘移位事务内延迟第一次同步，选区更新后提交一次；其他程序赋值和真人输入保持原路径。
3. **定位与失效处理**：滚动、容器尺寸/位置变化、卡片重建和异步翻译改变标签时，重新测量。插入线按画布缩放换算 CSS 坐标，drop 使用最终指针位置。结束/取消拖拽时清除状态。

## 对照结果

独立浏览器 DOM 夹具，直接执行生产拖拽函数；120 个 Tag、60 帧，每帧 4 次 dragover，共 240 次。两组在同一浏览器页面并列执行。

| 指标 | v0.4.34 | v0.4.35 |
| --- | ---: | ---: |
| 卡片位置读取 | 28,800 | 120 |
| 创建插入指示线 | 240 | 1 |
| 事件处理累计耗时 | 83.1 ms | 4.7 ms |
| 事件处理 p95 | 0.6 ms | 0.1 ms |

这只测拖拽处理函数，不包含 ComfyUI 大图状态、完整卡片工具栏、工作流序列化等成本，不能表述成“整个插件快 18 倍”。中位数可能低于浏览器计时精度，不用于计算倍数。

## 验证

- `node tools/test_prompt_drag.mjs`：静态布局测量预算、指示线复用、最终位置落点、滚动/布局/重建/翻译失效、0.1/0.5/1/2 倍缩放、方向切换、空列表与清理。
- `node tools/test_prompt_input_transaction.mjs`：排序单次提交、真人/程序输入兼容、嵌套及异常恢复、翻译版本失效、翻译中的重试标记。
- `node tools/test_widget_batch.mjs`：原有多控件事务回归。
- 35 项 Python 单元测试、JavaScript 语法检查及 Git 差异格式检查通过。
- 已检查独立浏览器夹具渲染并保存截图/JSON 到本地忽略目录 `output/performance/prompt-drag/`。
- 尚未在完整 ComfyUI 工作流中实测，也未运行完整前端兼容套件；原生鼠标拖放的整页体验仍需后续验证。

## 下一批建议（尚未实施）

| 优先级 | 方向 | 源码证据与风险 |
| --- | --- | --- |
| P1 | 工具栏按需创建 | `renderPromptChips` 为每个 Tag 提前构造全部工具按钮。先测创建/删除节点的耗时，再将工具栏改为首次悬停/聚焦时创建；需要验证键盘、权重、翻译和收藏入口。 |
| P1 | 卡片局部更新与 DOM 复用 | `updateCounters` 会调用 `renderPromptChips`，后者 `replaceChildren` 重建当前侧全部卡片。应区分文本/顺序/选区/计数变化；重复 Tag、分隔符、焦点和多选必须保真。 |
| P2 | 后台布局检查按需运行 | 接口标签覆盖层、尺寸自适应仍有周期检查，已有节流。先测大图/多个桥接节点的空闲 CPU，再决定是否增加可见性暂停或事件驱动；不能破坏平移、缩放后的自愈。 |

不建议为了“优化”同时重写所有模块；每次只改可复现热点，并保留对照及兼容回归。
