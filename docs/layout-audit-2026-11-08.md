# 布局修复与兼容性检查（v0.4.37）

日期：2026-11-08（Asia/Shanghai）。基线：v0.4.36 / `bd89177`。

## 已确认的问题

1. **大节点内部分区保持最小高度。** 用户现场外框 1539×1705，Prompt 220、LoRA 96，底部约 1294 个布局像素闲置。两个分区一旦有保存值，原来的自动填充均直接跳过；LoRA 的默认 520px 上限也阻止使用更大的节点空间。隔离实例的经典 LiteGraph、Nodes 2.0 均复现约 1293px 留白。
2. **原生尺寸参数兼容性。** `setSize` 包装器只接收普通 Array，宿主传入 Float32Array 时会绕过期望尺寸、保存尺寸及内部同步。修复接收有两个有效数值的数组视图；离线测试执行实际包装器验证该路径。
3. **缩放下错误的高度比较。** LoRA 可用高度校验将屏幕坐标中的缩放后高度与 CSS 布局高度比较；现统一使用布局像素。
4. **多个节点共用布局状态。** 序列化和侧栏 ResizeObserver 从全局 localStorage 重新读取当前值，可能将其他节点的分区/侧栏宽度应用到本节点。现存元素保存自己的首选高度和侧栏宽度；全局存储仅用于初始化默认值，手动拖动与重置同步更新该元素状态。
5. **快速 LoRA 浮层关闭丢失布局。** 打开时清空 LoRA 高度，关闭时只移除浮层 class，没有恢复分区。现保留高度并恢复浮层前的折叠状态及布局。
6. **Nodes 2.0 提示词小节点不断长高。** 正向/负向小节点将“节点高度减固定值”的控件留在 Vue 的普通文档流中，宿主再加上接口行高度，形成测量/resize 正反馈；真实页面展开词库后超过 5000px。现将该 Vue 控件宿主定位在真实接口行下方；忽略控件自身内部的 slot，避免定位反馈；适配百分比填充的 shell 健康检查，避免无效的反复修复。经典 LiteGraph 不走该定位分支。

## 修复原则

- 修复明显未分配空间或明显溢出，不清空用户全部布局配置，不修改节点执行参数、提示词内容、模型连线。
- 正常节点宽高保持不变；恢复一个可用 Prompt 区，再把多余空间交给可滚动 LoRA 区。对于用户主动保留的大节点，允许 LoRA 高于默认上限。
- 保留正常手动分区；忽略宿主工具栏/滚动条造成的小幅测量波动，避免缩放、折叠后反复改写尺寸。
- 面板未挂载/不可测量、正在拖动、LoRA 折叠或浮层打开时不进行这项空间修复。

## 实际本机复核

完整插件安装 `http://127.0.0.1:8188` 中的新验证页已自动恢复原异常工作流：外框仍为 1539×1705；初次恢复 Prompt 540、LoRA 1061、底部约 9px；最终新页面重载后 Prompt 535、LoRA 1050、底部约 25px（宿主工具栏/边距变化）。不再出现千余像素未分配空间，测试提示词保留。旧工作流先做本地备份，原用户标签页保留，验证页没有 Bridge 控制台错误。

- 浏览器布局矩阵 **28/28 通过**（14 个场景 × 两个渲染器）；最后对异常保存布局和真实手柄拖动再跑 **4/4 通过**，截图位于 `layout-final-targeted/`。
- 离线布局检查：**150 组尺寸组合**，另含小数边界、重复修复稳定性、独立节点首选高度、原生 Float32Array resize、Vue shell 防循环检查通过。

- 目视检查经典/Vue 修复后的大节点、小节点、实际本机页面；主 DOM 控件每节点保持 1 个。

这是有边界的布局兼容性检查，不等于穷尽任意浏览器、插件、主题及未来前端版本。当前宿主为 ComfyUI 0.20.1 / 前端 1.43.18。最初粉丝“内部全部为空”的图片仍缺准确环境和报错，不能据本次底部留白修复认定其问题必然同源或已解决。
